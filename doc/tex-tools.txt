*tex-tools.txt*  LaTeX editing with Tree-sitter and texlab

SETUP                                                   *tex-tools-setup*

Requires Neovim 0.11+ and the latex Tree-sitter parser, installed separately
(e.g. :TSInstall latex). Add the plugin to 'runtimepath', then: >lua
    require('tex-tools').setup({
      mappings = true,
      overwrite_mappings = false,
      smart_enter = false,
      conceal = false,
      math_environments = {},
    })
<
Commands/mappings attach to tex/plaintex buffers. Set g:maplocalleader before
loading. Existing mappings are preserved; mappings=false keeps commands and
<Plug> mappings. smart_enter enables list-aware Insert-mode <CR> when default
mappings are enabled. math_environments adds names, including starred forms.
Configure texlab, the compiler, and PDF viewer through your usual LSP setup.

CONCEAL                                                 *tex-tools-conceal*

Conceal is provided by Neovim, not texlab. Opt in with: >lua
    require('tex-tools').setup({ conceal = true })
    vim.opt.conceallevel = 2
    vim.opt.concealcursor = 'nc' -- Optional: conceal on the Normal cursor line.
<
All categories below default to true when conceal is enabled. A table enables
the feature with per-category overrides, e.g. conceal={cites=false, styles=false}.
conceal=false (default) or conceal={enabled=false} disables the renderer.

    accents          Single-letter accents: \'{e} -> é, \"o -> ö, \c c -> ç.
                     Only precomposed Unicode equivalents of ASCII letters.
    ligatures        Text ligatures (\ae{}, \OE{}, \ss{}, ...), dashes, quotes.
    cites            Parser-recognized citations: hide command/notes, preserve
                     keys in [] (or () for citep/parencite/autocite).
    fancy            \dots, \ldots, \textellipsis, \colon, \slash, \_, \item.
    spacing          Hide \, \; \: \! \quad \qquad and related spacing macros;
                     hide hspace/vspace/phantom arguments. ~ becomes a space.
    math_bounds      Hide matched $, $$, \(\), \[\] formula markers.
    math_delimiters  Hide left/right/middle and big/Big/bigg/Bigg sizing;
                     display directional bracket macros as Unicode.
    styles           Hide wrappers of common text/math formatting commands
                     (textbf, emph, textit, mathrm, mathbf, text, ...), keeping
                     their body and existing colors. Does not emulate fonts.
    math_symbols     Whitelisted Greek letters, operators, relations, sets,
                     arrows and large operators: \alpha -> α, \times -> ×.

Fractions, scripts and section headings retain source text.
Custom macro expansion is not inferred. Unknown/unsupported constructs remain
visible. Text accents/ligatures are disabled in math except within \text{...}.
Comments, literal/code environments, inline verbatim, definitions, paths, labels,
and citation-key spelling are protected. Citation notes are hidden by cites.

Math symbols are math-only; text mode suppresses them, while nested formulas
inside text start a new math context. Scripts, limits and arguments remain
source. Set conceal.math_symbols=false to disable built-in/custom symbols.
conceal.symbols maps bare command names (ASCII letters/@, no backslash) to one
printable Unicode character, or false to disable an entry. Example: >lua
    require('tex-tools').setup({
      conceal = { symbols = { alpha = 'Α', beta = false, RR = 'ℝ' } },
    })
<
Custom mappings replace the command itself without expanding its arguments.
The built-in whitelist is lua/tex-tools/conceal_symbols.lua.

The module loads only when enabled. Decorations are ephemeral and cached per
window for visible source lines; buffer text, syntax and highlight queries are
untouched. Scrolling reuses decorations in overlapping source lines.
conceal.max_line_length defaults to 10000 bytes; longer lines stay visible to
bound redraw work. Use 0 to disable this limit, or a nonnegative integer byte
limit. Expensive parses yield; source stays visible until ready. Missing
parsers fall back to source. A Tree-sitter highlighter is not started.
Native 'conceallevel' and 'concealcursor' control display; no window
options are changed. Disable overlapping VimTeX/legacy syntax conceal rules.

MAPPINGS                                                *tex-tools-mappings*

Existing mappings are preserved by default. To replace conflicting global or
buffer-local mappings with the plugin's default keys: >lua
    require('tex-tools').setup({ overwrite_mappings = true })
<
overwrite_mappings defaults to false and must be a boolean. It applies to all
default mapping modes, including Insert-mode <CR> when smart_enter=true.
mappings=false still disables default keys; commands and <Plug> mappings remain.
Replacements are buffer-local to tex/plaintex buffers. Repeating setup() with
overwrite_mappings=false or mappings=false restores replaced local mappings,
including Lua callbacks and options, and reveals current global mappings.
Cleanup preserves keys changed or deleted after attachment. Later mappings from
other plugins can still replace the plugin's keys.

Normal mode (each <Plug> name corresponds to a command below):

    <LocalLeader>lcd    <Plug>(TexToolsUnwrapCommand)
    <LocalLeader>lcs    <Plug>(TexToolsSurroundCommand)

    <LocalLeader>ldm    <Plug>(TexToolsJumpMathDelimiter)

selection; environment surrounds operate on whole selected lines.

To customize, use the individual <Plug> name: >lua
    vim.keymap.set('n', '<LocalLeader>lr', '<Plug>(TexToolsRenameEnvironment)')
    vim.keymap.set({ 'x', 'o' }, 'aE', '<Plug>(TexToolsAroundEnvironment)')
<
COMMANDS                                                *tex-tools-commands*

Omitted names/shapes open a prompt. Cancelled prompts do nothing; editing
the target buffer while a prompt is open invalidates the pending operation.

:TexToolsRenameCommand [name]                        *:TexToolsRenameCommand*
    Rename the innermost command, preserving arguments/options.
:TexToolsUnwrapCommand                               *:TexToolsUnwrapCommand*
    Remove a command with exactly one braced argument, preserving its body.
:[range]TexToolsSurroundCommand [name]              *:TexToolsSurroundCommand*
    Wrap the current line or line range in \name{...}.

:TexToolsRenameEnvironment [name]                 *:TexToolsRenameEnvironment*
    Rename both markers of the innermost environment.
:TexToolsToggleEnvironmentStar                *:TexToolsToggleEnvironmentStar*
    Add/remove a trailing * on both markers.
:[range]TexToolsSurroundEnvironment [name]      *:TexToolsSurroundEnvironment*
    Wrap the current line or line range; preserve body indentation.
:TexToolsUnwrapEnvironment                       *:TexToolsUnwrapEnvironment*
    Remove both markers and begin options, preserving the body.
:TexToolsJumpEnvironment                           *:TexToolsJumpEnvironment*
    Jump from begin/body to end, or from end to begin.

:TexToolsToggleMathDelimiters                   *:TexToolsToggleMathDelimiters*
    Switch $...$ <-> \(...\) or $$...$$ <-> \[...\], preserving math mode.
:TexToolsChangeMathDelimiters [shape]           *:TexToolsChangeMathDelimiters*
    Replace both math brackets, preserving size commands and body text.
:TexToolsUnwrapMathDelimiters                   *:TexToolsUnwrapMathDelimiters*
    Remove math bracket markers, preserving their contents.
:TexToolsToggleMathDelimiterSize             *:TexToolsToggleMathDelimiterSize*
    Add/remove \left and \right. See |tex-tools-math-brackets|.
:[count]TexToolsJumpMathDelimiter               *:TexToolsJumpMathDelimiter*
    Jump between matching bracket markers; count selects enclosing depth.

:TexToolsInsertItem                                     *:TexToolsInsertItem*
    Insert a sibling \item after the entire current item and enter Insert
    mode. Support itemize/enumerate/description; description opens the label.
    Create the first item in an empty list. Preserve existing body text.

:[count]TexToolsNextSection                           *:TexToolsNextSection*
:[count]TexToolsPreviousSection                   *:TexToolsPreviousSection*
    Jump to a section marker at any level.
:[count]TexToolsNextItem                                 *:TexToolsNextItem*
:[count]TexToolsPreviousItem                         *:TexToolsPreviousItem*
    Jump to an item marker at the current list level.
:[count]TexToolsNextEnvironment                   *:TexToolsNextEnvironment*
:[count]TexToolsPreviousEnvironment           *:TexToolsPreviousEnvironment*
    Jump to an environment opening, including nested environments/document.
:[count]TexToolsNextMath                                 *:TexToolsNextMath*
:[count]TexToolsPreviousMath                         *:TexToolsPreviousMath*
    Jump to a formula opening or math environment. See |tex-tools-navigation|.

:TexToolsBuild                                             *:TexToolsBuild*
    Save the current file and any modified main buffer with :update, then
    request a texlab build of the resolved main document.
:TexToolsMain [path|select|reset]                           *:TexToolsMain*
    Show, select or reset the main document for this texlab client/session.
    Paths are relative to the LSP root. select prompts for a file. reset
    restores build.main_file or source/root-directive discovery. Changes are
    refused while compiling or cleaning; source files are never rewritten.
:TexToolsInfo                                              *:TexToolsInfo*
    Show the main document, compiler, working directory and artifact paths.
    Lua main_file([path]) returns true, path or false, error; false resets
    the override (the resulting path may be nil if discovery is ambiguous).
    project_info() returns a snapshot or nil, error. Settings in it are copies.
    Manual builds target the selected main. Texlab's automatic builds retain
    its dependency-graph root selection. Save a modified child first or turn
    off build.onSave before manually building another main from that child.
:TexToolsForwardSearch                             *:TexToolsForwardSearch*
    Request texlab PDF forward search at the cursor without saving.
    Both commands require an attached texlab client and configured toolchain.

:TexToolsCancelBuild                               *:TexToolsCancelBuild*
    Cancel active builds in this buffer's texlab server instance.
:TexToolsCancelAllBuilds                            *:TexToolsCancelAllBuilds*
    Send cancellation to every running texlab server instance.
:TexToolsBuildStatus                               *:TexToolsBuildStatus*
    Show compilation state, elapsed time, build-on-save and the current
    compiler executable/profile. Compilation state describes the last build;
    compiler/profile describe the current configuration for subsequent builds.
:TexToolsBuildOnSave [on|off|toggle]                 *:TexToolsBuildOnSave*
    Change build.onSave for the attached client's current session. No argument
    toggles the setting. Other compiler settings remain intact.

Build management subscribes to native LspProgress after texlab attaches. Manual
builds report the response status; automatic builds report finished when their
progress ends, without inferring success from the end notification. Other LSP
progress handlers are preserved. A second manual build is rejected while one is
active in that client. A save that triggers build.onSave does not also send an
explicit build request. Cancellation is scoped to a server instance, not a file.

Lua: cancel_build(), cancel_all_builds(), build_on_save([boolean]) return
boolean[, result_or_error]. build_status() returns a copy with phase, uri,
on_save, result (when known), elapsed seconds, and error (when available), or
nil, error if no texlab client is attached. These functions need no setup().
build_status() also includes compiler (current executable) and profile (name
when current settings match a configured profile).

COMPILER PROFILES                                       *tex-tools-compiler-profiles*

:TexToolsCompiler [name|toggle]                     *:TexToolsCompiler*
    Without arguments show the current compiler and matched profile. With a
    name, switch the attached texlab client's configuration. toggle cycles
    profile names alphabetically; unmatched settings start at the first name.
    Names and toggle support command completion. No default mapping is added.

Define build.profiles in setup() (default {}): >lua
    require('tex-tools').setup({
      build = {
        profiles = {
          latexmk = {
            executable = 'latexmk',
            args = { '-pdf', '-synctex=1', '-interaction=nonstopmode',
                     '%f' },
          },
          tectonic = {
            executable = 'tectonic',
            args = { '-X', 'compile', '%f', '--synctex',
                     '--keep-logs', '--keep-intermediates' },
          },
        },
      },
    })
<
Profile names contain ASCII letters, digits, underscores, dots and hyphens;
the first character must be a letter, digit or underscore. toggle is reserved.
Each profile requires executable (a nonempty program name/path) and args (a
string list, replaced whole). Optional fields: auxDirectory, logDirectory,
pdfDirectory and filename (a nonempty basename). Other profile keys are errors.
Use latexmk's -xelatex instead of -pdf in a profile for XeLaTeX compilation.

Switching replaces all six profile fields. Omitted directory/filename overrides
are cleared to prevent a previous profile's paths from leaking into the next.
Repeat shared overrides in each profile that needs them. These settings locate
artifacts for texlab, log viewing and cleanup; also pass the compiler's output
arguments when needed. Deprecated texlab.auxDirectory is preserved alongside
other settings; prefer per-profile build directory overrides when switching.
onSave, forwardSearchAfter, forwardSearch and unrelated LSP settings are kept.

Switching checks local executable availability and refuses active builds or
cleaning. It sends workspace/didChangeConfiguration, without restarting texlab
or compiling. Local settings roll back if sending fails. The notification has
no server acknowledgement: success means sent; texlab applies asynchronously.
All buffers sharing the client see the change;
other clients keep their settings. No configuration files are written.
setup() does not select a profile, probe executables or start an LSP client.
Your LSP configuration determines the initial compiler, including after a
restart. Repeated setup() replaces the profiles without switching the compiler.

compiler([name])                                       *tex-tools.compiler()*
    Query when name is omitted; otherwise switch to name or 'toggle'. Return
    true, snapshot or false, error. snapshot contains profile (when matched),
    executable, args (when explicitly configured), and sorted profiles names.
    Returned tables are copies. Matching compares all six profile fields,
    independently of automatic compilation/PDF search settings. When identical
    profiles have multiple names, the selected name is retained while it still
    matches; otherwise the first matching name is used.

:TexToolsBuildOutput                               *:TexToolsBuildOutput*
    Open a read-only live compiler output split. q closes it; F toggles following
    new lines. Output resets each build and keeps at most build.output_lines
    lines (default 2000, positive integer). Existing LSP log handlers still run.
:TexToolsLog [path]                                *:TexToolsLog*
    Open a full .log read-only. An explicit path needs no LSP client. Otherwise
    resolve the main file through % !TeX root directives, build.main_file, or
    a standalone document's \documentclass. Ambiguous roots return an error.
    build.main_file defaults to false; a path is relative to the LSP root.
    Common output/jobname arguments and texlab logDirectory are respected.
    Latexmk directories/jobname are queried using -dir-report-only, including
    computed .latexmkrc values and -r files. Explicit texlab directory overrides
    take precedence. Discovery is cached until source/configuration files change;
    cleanup, preview and compilation options are excluded from the probe.
    Backends without a usable report need explicit directories or a log path.
    Discovered latexmk log directories are synchronized to texlab on attachment,
    TeX buffer changes and rc saves; explicit logDirectory overrides are kept.
    Omit -file-line-error so texlab can parse standard !-prefixed TeX errors.
    Recompile existing logs after removing that flag. Managed directory values
    are refreshed on rc/profile changes without changing compiler identity.
    A failed compiler can still produce PDF; its result remains a failure and
    the notification explains that the existing PDF may be incomplete.
:TexToolsErrors[!]                                 *:TexToolsErrors*
    Fill quickfix with errors and warnings from this texlab client only.
    With ! include errors only. Open the list only when nonempty. These output,
    log and diagnostic windows never open automatically after compilation.

Lua: build_output(), build_log([path]), build_errors([opts]) return
boolean[, result_or_error]. Results are an output buffer, log path, or diagnostic
count respectively. build_errors opts: errors_only (default false), open
(default true). Set open=false to fill quickfix without opening it.

:TexToolsClean                                     *:TexToolsClean*
    Remove auxiliary build artifacts for the resolved main file.
:TexToolsCleanFull                                 *:TexToolsCleanFull*
    Also remove the PDF. Refuse cleaning during compilation or another cleanup.
    latexmk delegates to texlab.cleanAuxiliary / texlab.cleanArtifacts, attaching
    the main document if necessary; completion/errors notify asynchronously.
    Tectonic compile cleanup removes exact files only: .aux, .out, .toc, .lof,
    .lot, .fls, .nav, .snm, .vrb, .synctex.gz, .log; full adds .pdf. Source,
    bibliography, .bbl and unrelated files are retained. Default output is the
    input directory; --outdir/-o and texlab auxiliary/log/PDF directories apply.
    No directory recursion occurs; leaf symlinks themselves are unlinked.
    Unsupported compilers, Tectonic project build/watch and ambiguous mains
    return errors. Directory paths in .latexmkrc are handled by texlab/latexmk.

Lua: clean([full]) returns true, request_id (latexmk), true, removed_count
(Tectonic), or false, error. full defaults to false. Compilation uses texlab's
process lifecycle; independent latexmk -pvc and region compilation are absent.

COMMAND EDITING                                         *tex-tools-command-editing*

Names omit the backslash: ASCII letters or @, optionally followed by *.
Environment names may also contain digits, underscores and hyphens.
Rename edits one invocation. Unwrap requires one braced argument without
options or non-group parameters. Visual command surrounds support character-
and linewise selections; blockwise selections and partial structures fail.
Edits reject invalid targets or text changes that would merge control words.

MATH BRACKETS                                           *tex-tools-math-brackets*

    Shape       Alias       Pair ~
    paren       (           ( )
    bracket     [           [ ]
    brace       {           \{ \}
    angle       <           \langle \rangle
    vert        |           \lvert \rvert
    Vert        \|          \lVert \rVert

Plain pairs and \left/\right pairs are supported in math context. Explicit
sized pairs may use mixed, invisible or symmetric markers; size toggling
requires matching visible directional markers. Plain symmetric bars, fixed sizes
(e.g. \bigl/\bigr), custom macros and ambiguous optional brackets are excluded.
Unwrap refuses orphaned \middle or discarded marker comments. Automatic
sizing cannot cross alignment cells/rows.

Bracket jumps go from body/opening to closing, or closing back to opening;
sized pairs land on \left/\right. Counts select enclosing depth at the
current cursor, as with ad/id. Unavailable depth cancels the jump.

NAVIGATION                                              *tex-tools-navigation*

Section/environment/formula motions traverse the buffer in source order;
item motions stay in the nearest itemize/enumerate/description environment.
Nested list environments are skipped. Counts select successive targets;
oversized counts stop at the furthest available target without wrapping.
Successful jumps record the previous context and open destination folds.
No target leaves cursor/jump history unchanged. Navigation is Normal-mode
only and works in unmodifiable buffers. Comments, literal content, and
parser-recognized definition bodies are skipped as navigation targets.

TEXT OBJECTS                                            *tex-tools-textobjects*

    Around  Inside  Target / inner selection ~
    ae      ie      Environment / body without begin options or marker lines
    ac      ic      Command call / name without backslash, including star
    aa      ia      Curly or bracket group / contents
    a$      i$      Formula or math environment / body
    ad      id      Math brackets including sizing / contents
    ai      ii      List item including marker and label / trimmed body

Use Visual or operator-pending mode (e.g. dai, cii, y2ia). Counts select
enclosing depth of the same kind, never siblings; operator counts multiply
(2d2ac selects depth four). Empty inner objects and unavailable depths cancel
the operator, preserving text/registers and the preceding repeat.

Item objects support itemize/enumerate/description, continuation paragraphs,
and nested lists. Default depth stays at the nearest list level; 2ai selects
the parent item. Blank gaps use the preceding item. Whole-line ai is linewise
and includes indentation, the final newline and its trailing comment; following
blank lines/standalone comments remain. Other selections are characterwise.
ii excludes marker/label/separating whitespace, keeping escaped trailing spaces.
Finish description labels if the parser treats \item[] as incomplete syntax.

LIST ENTER                                              *tex-tools-smart-enter*

Enable smart_enter to split nonempty list items at the cursor, preserving
the suffix and continuation paragraphs/nested lists. Use native Enter for
empty items, comments, unsupported contexts, or missing syntax. Explicit
|:TexToolsInsertItem| inserts after the whole item and can create the first.
One undo removes the insertion/split and immediately typed text.
For an existing completion mapping, call smart_enter() in its fallback branch;
see |tex-tools.smart_enter()| for the expression mapping options.

REPEATING EDITS                                         *tex-tools-repeat*

Cursor-based command/environment rename and unwrap, environment star toggling,
math bracket edits, and formula delimiter switching support native |.|.
Reuse the resolved name/shape without prompting. [count]. repeats at the same
cursor, stopping on an invalid target; successful iterations share one undo.
Surrounds and list input do not register structural repeats. Text-object
operators keep native repeats. Failed/cancelled edits preserve the preceding
repeat. API edits register repeats only in Normal mode in the current buffer.

LUA API                                                 *tex-tools-api*

All functions are available from require('tex-tools'), without setup().
Queries/jumps never notify; editing functions return true or false, error.
With an omitted name, true means the asynchronous prompt opened.
Ranges are {start_row, start_byte, end_row, end_byte}, zero-based/end-exclusive.
Query opts: {bufnr, pos={row, byte_column}}, defaulting to the current cursor.
A different buffer requires pos. Missing parser/invalid positions return
false/nil, error. TeX macros and custom command signatures are not expanded.

in_math([opts])                                          *tex-tools.in_math()*
    Boolean: math mode, including configured math_environments. \text{...}
    suppresses outer math; a nested formula enables math again.
in_comment([opts])                                    *tex-tools.in_comment()*
    Boolean: LaTeX comment; literal/code content is not a comment.
in_subscript([opts])                                *tex-tools.in_subscript()*
in_superscript([opts])                            *tex-tools.in_superscript()*
    Boolean: mathematical _/^ payload. Exclude the operator/opening brace;
    include the insertion position before a closing brace, even in empty
    groups. Unbraced payloads are end-exclusive. Nested scripts can match both.
in_numerator([opts])                                *tex-tools.in_numerator()*
in_denominator([opts])                            *tex-tools.in_denominator()*
    Boolean: nearest \frac/\dfrac/\tfrac part with two complete braced
    arguments. Use the same insertion boundaries as scripts. Inner fractions
    have their own role; unbraced fractions and custom aliases do not match.
in_table_cell([opts])                              *tex-tools.in_table_cell()*
    Boolean: body cell in tabular/tabular*/tabularx, array, matrix/pmatrix/
    bmatrix/Bmatrix/vmatrix/Vmatrix/smallmatrix, cases, aligned/alignedat,
    align/alignat/flalign/split, including stars. Exclude headers, column specs,
    structural & and row breaks (including spacing), and common table rules.
    Nested groups/commands/formulas remain in their cell. The nearest
    environment must be supported and complete; visual columns/spans are
    not inferred.

Detailed math queries stop at the nearest formula/math environment. Comments
and literal content suppress these predicates (except in_comment). Ordinary
nonmatching contexts return false without an error. For LuaSnip, use a wrapper
so its arguments are not interpreted as opts: >lua
    local in_power = function() return require('tex-tools').in_superscript() end
<

    Return encoded keys for an Insert-mode expression mapping: >lua

PDF VIEWING AND INVERSE SEARCH                     *tex-tools-viewer*

:TexToolsView opens the resolved PDF without a source-line jump. An attached
texlab client is required for project resolution. No forward request is sent.
viewer.method: auto (default), zathura, skim, generic.
viewer.executable: false (default) or an executable override.
viewer.args: extra arguments before the PDF path (default {}).
Auto detects Skim from texlab displayline, Zathura from texlab/PATH, then the
system opener. Skim uses open -a Skim (executable overrides open); Zathura uses
zathura; generic uses open, explorer.exe or xdg-open. Generic openers do not
configure synchronization. Viewing does not require an existing SyncTeX file.

:TexToolsInverseSearch [skim|zathura] displays a stable native callback.
Skim: copy Command and Arguments into Settings > Sync > Custom once.
Zathura started through :TexToolsView receives its callback automatically.
The same command works after restarting Neovim; open a local TeX file with
this plugin enabled to register the new session. PDF windows can stay open.
Replace the older session-specific callback once when upgrading. Regenerate
only if the executable, plugin path or cache location/NVIM_APPNAME changes.
No nvim-texlabconfig, service, or extra plugin is needed. A clean headless
Neovim discovers the owning instance and passes filenames as RPC arguments.

Routing prefers an already-loaded source, then the most specific matching
texlab workspace, then the instance most recently active in a TeX buffer.
Unrelated instances are not used. Unopened children need a matching workspace.
Private per-process records live in stdpath('cache')/tex-tools/inverse-search.
Writes are atomic; normal exit removes the record. Lookup prunes dead or
unreachable sessions; unresponsive sessions time out. Callback generation
supports POSIX systems (macOS/Linux). The viewer and editor must share access
to the registry and socket. Viewer preferences are never modified automatically.

Forward search normally uses texlab. An explicit main (TexToolsMain or
build.main_file), or effective latexmk artifact discovery, instead expands
texlab.forwardSearch executable/args directly:
%p selected PDF, %f current source, %l current line. Configure these texlab
settings first. Arguments are argv entries, not shell commands. Synchronization
requires SyncTeX support in the compiler and viewer (Tectonic: --synctex).

view() returns true, job_id or false, error.
inverse_search(file, line [, column]) returns true or false, error. Positions
are one-based; column counts bytes. A modified buffer is preserved.
inverse_search_command(kind) returns {command, arguments, argv, shell_command,
registry, server} or nil, error. server is informational and not in the command.
RPC starts on demand when registering a named local TeX buffer or generating
a callback. Registration is scheduled after buffer setup, once per process.
Subsequent buffer/focus events update activity in memory. Setup with no named
local TeX buffer and health checks do not start a server.
The User TexToolsInverseSearch event supplies file/line/column data. External
terminal activation can be configured on that event; it is not automatic.

TABLES AND MATRICES                                     *tex-tools-tables*

:[count]TexToolsNextCell                            *:TexToolsNextCell*
:[count]TexToolsPreviousCell                        *:TexToolsPreviousCell*
    ]t / [t traverse cells across rows. Counts, jump history and fold opening
    are supported. Nested groups/commands/formulas/environments are atomic.
    No wrapping occurs; unavailable counts leave the cursor unchanged.
    at / it select a cell with/without whitespace, excluding separators.
    Empty inner cells and counts other than 1 cancel the operator.
:TexToolsInsertRow                                 *:TexToolsInsertRow*
:TexToolsDeleteRow                                 *:TexToolsDeleteRow*
    Insert an empty row after the cursor's row, or delete that row.
:TexToolsInsertColumn                              *:TexToolsInsertColumn*
:TexToolsDeleteColumn                              *:TexToolsDeleteColumn*
    Insert after the current column (copying its alignment), or remove the
    column from every row. Update plain l/c/r/X table/array preambles.
    Matrix environments need no preamble. Alignment/cases column edits fail.

Row/column edits require equal-width rows, each on a dedicated source line.
Comments, rule commands, spans and nested environments are refused. The only
row/column cannot be deleted. Complex preambles refuse column edits. Row-break
options are preserved. Edits support dot repeat and one-step undo.
Navigation/objects use the environments listed at in_table_cell(), with the
nearest supported environment taking precedence; they accept complex content.

Lua: jump_cell(direction [, count]), table_edit(operation), and

SECTION LEVELS                                          *tex-tools-section-levels*

:[count]TexToolsPromoteSection                      *:TexToolsPromoteSection*
:[count]TexToolsDemoteSection                       *:TexToolsDemoteSection*
    Shift the current section and every descendant heading by count levels
    (default 1). Promote moves toward part; demote toward subparagraph.
    Order: part, chapter, section, subsection, subsubsection, paragraph,
    subparagraph. The document class must support the resulting commands.
    Stars, short titles, labels and body text are preserved. Comments,
    definitions and literal environments are skipped. Any boundary overflow
    or incomplete heading rejects the whole edit. Only this buffer is edited.
    Dot repeat and single-step undo are supported; no default keys.

Lua: shift_section(direction [, count]) returns true or false, error.
direction: -1 promotes, 1 demotes. Plug mappings: TexToolsPromoteSection,
TexToolsDemoteSection. A count shifts levels, rather than selecting ancestors.

OUTLINE                                                 *tex-tools-outline*

Heading/include snapshots are cached as plain data for up to 128 sources and
8 MiB of source size. Edits, undo, buffer load/unload and disk-file metadata
changes invalidate the relevant snapshot. Unchanged ordinary buffers reuse
their current LaTeX tree; inline verbatim is masked in a separate parse.

:TexToolsOutline[!] [query]                           *:TexToolsOutline*
    Show a searchable outline in a native split. Without ! use this buffer;
    with ! resolve the main document and expand literal input/include files
    in source order. Main selection follows TexToolsMain/build.main_file/root
    directives; texlab is optional. Unnamed buffers support current-file mode.
    Default mapping: <LocalLeader>lt. Plug mappings: TexToolsOutline and
    TexToolsProjectOutline (no default project key).

The panel shows title (short title preferred), hierarchy, stars and file:line.
> marks the current section. / searches; f prompts for a case-insensitive title
or path substring (empty clears); <CR> jumps; r refreshes; q closes. query sets
the initial filter. Modified buffers are read without saving. A cross-file jump
preserves an unsaved origin even when 'hidden' is off.

Includes resolve against the compilation working directory, then the including
file's directory. Cycles, missing files and nonliteral includes produce warnings;
repeated noncyclic includes are shown. Definitions/comments/literal content and
inline verbatim are skipped. No macro, conditional, includeonly or TEXINPUTS
evaluation occurs. Limits per refresh: 256 file visits, 32 nested includes,
2 MiB per disk file, 8 MiB total source. Exceeding a limit returns an error.

outline([opts])                                      *tex-tools.outline()*
    Return true, panel_buffer or false, error. opts: project=false, query=''.
outline_entries([opts])                      *tex-tools.outline_entries()*
    Return {entries, warnings, root, project} or nil, error. opts also accepts
    bufnr and zero-based pos. Entries have path, optional bufnr, zero-based
    row/col, level (part=1 through subparagraph=7), kind, title, starred and
    optional current. Returned data contains no Tree-sitter nodes.
